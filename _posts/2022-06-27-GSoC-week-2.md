   can drop `git sparse-checkout reapply` from the tests, as [suggested](

   first one.

3. Fix the commit message of "mv: use flags mode for update_mode", as suggested
   [here](https://lore.kernel.org/git/01b39c63-5652-4293-0424-ff99b6f9f7d2@github.com/).

4. Add "Helped-by" and "Suggested-by" trailers.

5. In "mv: add check_dir_in_index() and solve general dir check issue", change
   the `check_dir_in_index()` to no more accept `namelen` as argument. The

   has a trailing slash. So just use `strlen()` to save the trouble.

## What's learned this week

1. Make sure a commit does one thing, and the commit message should
describe it well. An atomic commit makes the history more reasonable
and helps the future developers to clearly see the intention and result
of it.

2. Don't forget to credit people who helped you. By using "Helped-by" 
and "Suggested-by" trailers, people helped you can also be recorded into
the history. One of the best ways to be grateful. If you find this
etiquette interesting

3. Read the documentation. I haven't read the [CodingGuidelines](
    https://github.com/git/git/blob/master/Documentation/CodingGuidelines
)
thoroughly. It specifies all the styling conventions and things to be
careful about. One of the consequences of not spending 15 minutes going over
the doc, is keeping making styling mistakes like me: I have taken a
tab width of 4 spaces for granted, and didn't expect the Git project
uses a tab width of 8 spaces in the C files. This misunderstanding
always makes my code looks wrongly indented. Keep calm and read the doc.
